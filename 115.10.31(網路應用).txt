一、 核心觀念：網路通訊與郵件比喻
--------------------------------------------------------------------------------
1. 通訊邏輯：
   - 網路封包傳送就像實體寄信/包裹，需要明確的寄件人、收件地址與轉運節點。
2. 常用名詞對應：
   - FQDN（完全合規網域名稱）：如 www.hackthebox.eu，相當於現實中的「建築物名稱」。
   - URL（統一資源定位器）：如 https://www.hackthebox.eu/example，相當於精確到「幾樓、哪間辦公室、找誰」。
   - ISP（網際網路服務供應商）：扮演「總郵局」角色，負責處理進出公網的封包轉發。
   - 路由器（Router）：扮演「本地郵局/分發員」，負責連接不同網段並轉發資料。
   - DNS（網域名稱系統）：網路世界的「查號台/地址名冊」，負責將文字網址解析為實際通訊用的 IP 位址。

三、 企業網路切分與資安防禦重點（五大關鍵隔離）
--------------------------------------------------------------------------------
※ 為什麼重要：若企業內網採用扁平化架構（Flat Network），攻擊者一旦突破邊界拿下一台電腦，
   就能直接橫向移動（Lateral Movement）打下整個網段。

1. Web 伺服器放置於 DMZ（非軍事區）：
   - 原因：公開對外的服務被攻擊與滲透的風險最高。
   - 防禦：將 Web 伺服器獨立切在 DMZ 網段，即使被攻陷，攻擊者也無法直接碰觸內部核心伺服器與資料庫。

2. 工作站與外部服務間的嚴格防火牆規則：
   - 原因：防止攻擊者在內網發動位址偽造、中間人攻擊（MITM）或橫向探測。
   - 防禦：落實微切分（Micro-segmentation），限制主機間非必要的直連埠位。

3. 網路設備的管理介面獨立（Management VLAN）：
   - 原因：交換器與路由器的 Console/SSH/Web 管理後台極具戰略價值。
   - 防禦：必須放在專屬受限的「管理網路」，一般員工電腦完全無法路由或連線至管理介面，杜絕 ARP 欺騙與封包監聽。

4. IP 電話獨立 VLAN（Voice VLAN）：
   - 安全原因：防止語音封包（VoIP）遭到內網封包嗅探（Sniffing）或竊聽。
   - 維運原因：可設定 QoS（服務品質保證），確保語音頻寬優先，降低網路延遲與抖動。

5. 印表機必須獨立網段並嚴格限縮連線：
   - 原因：印表機韌體更新慢、漏洞多、安全性普遍極低，極易成為攻擊者建立持久化後門（Persistence）的跳板。
   - 認證風險：在 Windows 網域環境中，若印表機發出需要認證的提示，Windows 主機可能會嘗試以 NTLMv2 進行驗證，
     攻擊者可藉此攔截或竊取使用者的 Hash 密碼雜湊。
   - 防護原則：
     * 印表機禁止直接連線至網際網路（Internet）。
     * 工作站不得任意直連印表機敏感 Port（如 SMB Port 445）。
     * 印表機不得具備主動發起對工作站連線的權限（僅能由特定列印伺服器轉送）。

四、 實戰情境借鏡（實體滲透測試案例）
--------------------------------------------------------------------------------
- 攻擊手法：
  滲透測試人員將內建反向連線（Reverse Shell）的印表機假借包裹寄送至客戶公司，
  員工誤以為是新設備直接插上企業內網，成功繞過外部所有防火牆邊界防禦。
- 根本成因：
  企業未落實 NAC（網路存取控制）與印表機網段隔離，導致未授權設備插線即可通網並對外回連。

================================================================================
網路基礎與資安核心觀念記憶口訣
================================================================================

1. 角色分工口訣：
   「路由器是導航郵差管指路，Web 伺服器是店家廚房出內容。」
   ※ 說明：誰是請求發起方，對應的伺服器才開工；連外部網站時，是外部目標網站的伺服器在運作，自家的 Web 伺服器不參與。

2. 安全隔離口訣：
   「對外的丟 DMZ，脆弱的關禁閉，管設備的走暗道。」
   - 對外丟 DMZ：Web 伺服器對外風險高，必須獨立切至非軍事區防護。
   - 脆弱關禁閉：印表機、IP 電話等 IoT 設備漏洞多，需各切專屬網段（VLAN）嚴格限制存取。
   - 管設備走暗道：交換器、路由器的後台管理介面必須放在受保護的獨立管理網段。

3. 駭客突破口訣：
   「進不來就用寄的，連不進就讓它反向連出來（Reverse Shell）。」
   ※ 說明：外部防火牆阻擋連入時，利用社交工程或硬體寄送將後門帶入內網，透過反向連線繞過對外防火牆限制。

【Hack The Box】網路類型與 VPN 安全實務筆記 (Network Types & VPNs)
================================================================================

一、 私有 IP 範圍 (RFC 1918 必背標準)
--------------------------------------------------------------------------------
1. 10.0.0.0/8       (10.0.0.0 - 10.255.255.255)       -> 企業大型內部網路
2. 172.16.0.0/12    (172.16.0.0 - 172.31.255.255)     -> 實驗室/中型內網
3. 192.168.0.0/16   (192.168.0.0 - 192.168.255.255)   -> 小型辦公室/家用網段

二、 滲透測試員致命疏忽：子網路遮罩判斷
--------------------------------------------------------------------------------
- 錯誤習慣：看到 192.168.1.X 就下意識認為遮罩是 /24 (255.255.255.0)。
- 潛在陷阱：若遮罩為 /25 (255.255.255.128)，同一個 C 段已被切為兩個獨立廣播域。
- 實戰影響：若未精確核對子網路遮罩，會漏掃另一半網段的主機，誤以為高價值
  伺服器不存在而導致滲透中斷。

三、 三大 VPN 類型與滲透防禦觀點
--------------------------------------------------------------------------------
1. Site-to-Site VPN (站對站 VPN)：
   - 連接總部與各分公司路由器/防火牆，整段網路互通。
   - 滲透思維：打下防禦最薄弱的分公司邊界設備，即可透過隧道橫向打入總部核心。

2. Remote Access VPN (遠端存取 VPN / Client-to-Site)：
   - 員工在家透過 OpenVPN / WireGuard 等軟體連回公司內網。
   - Split-Tunneling (分割通道) 風險：
     * 概念：僅內網網段流量走 VPN，其餘上網流量走一般網路。
     * 風險：若員工私人設備被黑客控制，黑客可將其當作「跳板 (Pivot)」，
       繞過外部防線直接橫向移動進入企業內網。

3. SSL VPN (基於 Web 瀏覽器)：
   - 透過瀏覽器運作的連線（如 HTB Pwnbox），不需額外安裝客戶端。

【外部打擊原則】
1. 人在靶機外面：
   - 核心目標：針對目標 IP 找出所有「開放端口」與「背後的軟體版本」。
   - 心態：不要死背指令參數，隨時 Google / man 查語法即可；重點是「全端口快掃」搭配「開放端口版本深搜」。

2. 打進靶機內部：
   - 核心目標：查本機監聽服務與網路設定（IP、子網路遮罩、路由表、ARP 快取）。
   - 心態：定位自己是誰（Web/員工電腦）、人在哪裡（DMZ/內網），尋找雙網卡機器做跳板橫向移動。

【Hack The Box】進階網路拓撲補充筆記 (Tree, Hybrid, Daisy Chain)
================================================================================

1. 樹狀拓撲 (Tree Topology) -> 大型企業大樓/校園標準架構：
   - 特徵：星狀結構的層級化延伸（階層式架構）。
     * 頂層：核心伺服器 (Server) / 核心路由器。
     * 中層：各樓層/各部門乙太網路交換器 (Ethernet Switches)。
     * 底層：終端使用者電腦 (Host A ~ F)。
   - 滲透思維：攻擊路徑通常由底層葉節點（員工電腦）逆向往上，滲透中層交換設備，
     最終奪取頂層核心伺服器與資料庫控制權。

2. 混合拓撲 (Hybrid Topology) -> 真實企業網路現況：
   - 特徵：結合多種基礎拓撲（如星狀+網狀+樹狀）。
   - 滲透思維：在複雜的混合架構中，容易存在「配置疏漏的互聯路由器/跳板」，
     可用於繞過主幹線的防火牆阻擋。

3. 菊花鏈 (Daisy Chain) -> 邊緣/工控環境：
   - 特徵：設備首尾相連成一串（常見於工控自動化 CAN 領域）。
   - 特點：單點故障風險高，中間節點斷線則後續全部中斷。

一、 模型對照與 PDU 完整結構圖 (對應教材圖表)

+---+--------------------+------------------+------------------+---------------+
| 4 | Transport 傳輸層   | 3. Transport     | Segment (區段)   | TCP, UDP
|   |                    |    傳輸層        | / Datagram       | (以 Port 為主)
+---+--------------------+------------------+------------------+---------------+
| 3 | Network 網路層     | 2. Internet      | Packet (封包)    | IP, ICMP
|   |                    |    網際網路層    |                  | (Router 路由器)
+---+--------------------+------------------+------------------+---------------+
| 2 | Data-Link 資料鏈結層| 1. Link / Network| Frame (訊框)     | MAC, ARP

二、 封裝 (Encapsulation) 與解封裝 (Decapsulation) 運作流程
--------------------------------------------------------------------------------
1. 傳送端 (由上往下打包 - 穿衣服)：
   - [資料 Data] 
     ↓
   - [TCP Header] + [Data] ------------------------> 形成 Segment
     ↓
   - [IP Header] + [TCP Header] + [Data] ----------> 形成 Packet
     ↓
   - [MAC Header] + [IP] + [TCP] + [Data] + [CRC] -> 形成 Frame
     ↓
   - 轉換成實體電氣訊號/光訊號 (Bits 0與1) 傳輸至網路線。

2. 接收端 (由下往上拆包 - 脫衣服)：
   - 網卡收訊 (Bits) → 拆 MAC 檢查是否給自己 (Frame) → 拆 IP 看目標位址 (Packet)
     → 拆 TCP 找對應 Port 程式 (Segment) → 還原原始內容給瀏覽器/應用程式 (Data)。

三、 滲透測試與資安攻防對應層級
--------------------------------------------------------------------------------
- L7 (應用層攻擊)：SQL 注入 (SQLi)、跨站腳本 (XSS)、Web Shell。
- L4 (傳輸層探測)：Nmap SYN 掃描 (-sS)、UDP 端口探測、TCP 三向交握劫持。
- L3 (網路層滲透)：IP 偽造 (Spoofing)、Ping 掃描 (ICMP)、跨網段路由分析。
- L2 (鏈結層攻擊)：ARP 欺騙 (ARP Poisoning)、區域網路中間人監聽 (MITM)。
================================================================================

【秒記版】OSI 7層與網路模型實戰白話筆記
================================================================================

【白話寄信四步記法】
1. L2 (資料鏈結層 - MAC)：
   - 白話：同一個辦公室直接喊名字（區域網路交換器）。
   - 滲透：ARP 欺騙、內網中間人監聽。

2. L3 (網路層 - IP)：
   - 白話：跨區寄信要寫的收件地址（路由器負責送）。
   - 滲透：私有 IP 範圍判斷、子網遮罩網段確認。

3. L4 (傳輸層 - Port/端口)：
   - 白話：到地址後要敲哪一扇門（TCP / UDP 門號）。
   - 滲透：Nmap 端口快掃、TCP 三向交握探測。

4. L7 (應用層 - Data/內容)：
   - 白話：拆開包裹看到的東西（網頁、程式碼、圖片）。
   - 滲透：Web 漏洞（SQLi、XSS）、反彈 Shell 傳送指令。

※ 快速結論：
打靶機時，L4 找破門（掃 Port），L7 鑽進去（打 Web 漏洞），進去後看 L3（IP 網段）準備橫向移動。

================================================================================
【Hack The Box】OSI 7層架構定義與運作機制 (OSI Model Breakdown)
================================================================================

一、 核心兩大群組 (高低層劃分)
--------------------------------------------------------------------------------
1. 傳輸導向層級 (Transport-oriented / L2 - L4)：
   - 包含：資料鏈結層 (L2)、網路層 (L3)、傳輸層 (L4)。
   - 核心職責：負責資料的定址、路徑選擇、流量控制與傳輸可靠度，確保封包順利送達。

2. 應用導向層級 (Application-oriented / L5 - L7)：
   - 包含：會議層 (L5)、展示層 (L6)、應用層 (L7)。
   - 核心職責：負責應用程式介面、資料格式轉換/加密編碼，以及使用者會話管理。

二、 雙向通訊運作流程 (執行兩次原則)
--------------------------------------------------------------------------------
一次完整的網路通訊，雙方主機皆需運作該模型（至少執行兩次）：
1. 發送端 (由上往下 7 -> 1 / 封裝)：
   - 應用程式產生資料 -> 格式編碼/加密 -> 建立連線會話 -> 切割區段 (Port)
     -> 加上 IP 位址 -> 加上 MAC 位址 -> 轉為電氣/光訊號送出。
2. 接收端 (由下往上 1 -> 7 / 解封裝)：
   - 接收實體訊號 -> 解碼 Frame -> 檢查 IP 路由 -> 比對 Port 分發程式
     -> 會話還原 -> 解密/格式轉換 -> 最終應用程式呈現資料。

三、 各層功能速查
--------------------------------------------------------------------------------
- L7 Application (應用層)：使用者與軟體介面，提供應用程式網路服務。
- L6 Presentation (展示層)：資料格式化、語法轉換、壓縮與加密 (如 TLS/SSL)。
- L5 Session (會議層)：建立、管理與終止兩端系統之間的通訊會話 (Session)。
- L4 Transport (傳輸層)：提供端到端傳輸控制 (TCP/UDP)、資料切割與重組。
- L3 Network (網路層)：邏輯定址 (IP) 與路徑選擇 (Routing 路由轉發)。
- L2 Data-Link (資料鏈結層)：物理定址 (MAC)、錯誤偵測與無差錯傳輸。
- L1 Physical (實體層)：規範實體介質的電氣特性、電壓、光訊號與位元傳輸。

二、 TCP/IP 協定的 5 大核心任務與對應協定
--------------------------------------------------------------------------------
1. 邏輯定址 (Logical Addressing) -> [IP 協定]：
   - 負責分配全域唯一的邏輯 IP 位址，定義子網路與主機位置。

2. 路由轉發 (Routing) -> [IP 協定]：
   - 路由器根據封包內的目標 IP 位址，決定跨網段的最佳傳輸路徑。

3. 錯誤與流量控制 (Error & Control Flow) -> [TCP 協定]：
   - 追蹤確認封包送達狀況，遇遺失則要求重傳，維護資料傳輸完整性。

4. 應用支援 (Application Support) -> [TCP / UDP 協定]：
   - 透過 Port (連接埠) 號碼，將傳入的資料正確交給對應執行的應用程式。

5. 名稱解析 (Name Resolution) -> [DNS 協定]：
   - 將文字網域名稱 (FQDN) 轉換解析為底層通訊使用的 IP 位址。

三、 滲透測試實戰意義
--------------------------------------------------------------------------------
- Nmap 掃描：本質就是在探測第 3 層 (Transport) 的 TCP/UDP Port 是否開放。
- 網路嗅探 (Sniffing)：在第 1 層 (Link) 與第 2 層 (Internet) 攔截封包並解析內容。
- 服務識別：針對第 4 層 (Application) 確認該 Port 跑的具體軟體與版本 (如 Apache/OpenSSH)。

================================================================================
【Hack The Box】第 3 層：網路層 (Network Layer) 核心筆記
================================================================================

一、 核心職責與兩大功能
--------------------------------------------------------------------------------
網路層（Layer 3）負責端到端（End-to-End）的封包交換與路徑選擇。
即便發送端與接收端處於完全不同的網路架構或跨國網段，也能順利送達。

1. 邏輯定址 (Logical Addressing)：
   - 分配邏輯識別碼（IPv4 / IPv6），定義設備在網路中的唯一身份與子網位置。
2. 路由選擇 (Routing)：
   - 路由器根據「路由表 (Routing Table)」，逐跳（Hop-by-Hop）轉發封包至下一站節點。
   - 特點：L3 轉發節點僅檢查網路層位址，不拆解、不干涉更高層級（L4-L7）的資料內容。

二、 常見核心協定與資安實戰意涵
--------------------------------------------------------------------------------
1. IPv4 / IPv6 (網際網路協定)：
   - 封包封裝的基礎，定義來源 IP 與目標 IP。
   - 滲透思維：IP 偽造 (IP Spoofing)、繞過特定來源 IP 白名單。

2. ICMP (網際網路控制訊息協定)：
   - 用於回報錯誤、網路診斷與探測。
   - 工具對應：Ping (ICMP Echo Request/Reply)、Traceroute。
   - 滲透思維：Ping Sweep 批量主機存活探測；若防火牆封鎖 ICMP，需改用 TCP/UDP 探測。

3. IPsec (網際網路安全協定)：
   - 在網路層提供封包加密與身份驗證，常用於 Site-to-Site VPN 隧道。

4. OSPF / RIP (動態路由協定)：
   - 路由器之間自動交換路由資訊與網路拓撲變化的協定。
   - 滲透思維：若未配置身分驗證，攻擊者可在內網偽造 OSPF 宣告發動路由劫持 (MITM)。
================================================================================

【Hack The Box】IPv4 定址、二進位計算與 CIDR 核心筆記
================================================================================

一、 IPv4 結構與二進位權重對照
--------------------------------------------------------------------------------
1. 基礎結構：
   - IPv4 總長度為 32 位元 (Bits)，由 4 個 8 位元組 (Octets) 組成，以點分隔十進位表示。
2. 8 位元二進位權重值 (八位元組計算基石，必背)：
   Bit 位置:    1    2    3    4    5    6    7    8
   權重數值:  128   64   32   16    8    4    2    1
   - 範例：二進位 11000000 = 128 + 64 = 192
   - 範例：二進位 11111111 = 128 + 64 + 32 + 16 + 8 + 4 + 2 + 1 = 255

二、 網段中的保留與關鍵位址 (扣除兩顆 IP 原理)
--------------------------------------------------------------------------------
在任何可分配主機的子網段中，可用 IP 數為 (2^主機位元數 - 2)：
1. 網路位址 (Network Address)：
   - 該網段的第一個 IP（主機位全為 0），代表網段本體，不可配給端點設備。
2. 廣播位址 (Broadcast Address)：
   - 該網段的最後一個 IP（主機位全為 1），用於向同網段所有設備發送廣播，不可配發。
3. 預設閘道 (Default Gateway)：
   - 區域網路跨網段出口（通往路由器的 IP），慣例使用第一個可用 IP (如 .1)
     或最後一個可用 IP。

三、 CIDR (無類別域間路由) 與遮罩速查
--------------------------------------------------------------------------------
CIDR 斜線表示法 (/N) 代表子網路遮罩二進位中前 N 個位元為 1 (網路部分)：
- /8  : 255.0.0.0         -> 早期 Class A，可用主機約 1,677 萬台
- /16 : 255.255.0.0       -> 早期 Class B，可用主機 65,534 台
- /24 : 255.255.255.0     -> 早期 Class C，可用主機 254 台 (最常見辦公網段)
- /25 : 255.255.255.128   -> 將 C 段一分為二，每段可用主機 126 台

四、 滲透測試實務應用
--------------------------------------------------------------------------------
- Nmap 網段探測指令：
  * `nmap -sn 192.168.1.0/24`：探測該 C 段 254 台主機誰在線 (Ping Sweep)。
- 權限維持與跳板判斷：
  * 拿下的主機若是 `10.10.10.5/16`，代表橫向移動的探索範圍不是 254 台，
    而是整整 6 萬多台內網主機！

【Hack The Box】子網路劃分 (Subnetting) 實戰口訣筆記
================================================================================

一、 核心觀念：切蛋糕原理
--------------------------------------------------------------------------------
1. 每一組 IP 永遠有兩個不可用的保留位：
   - 第一個號碼 (起點)：網路位址 (Network Address) -> 網段的招牌名字。
   - 最後一個號碼 (終點)：廣播位址 (Broadcast Address) -> 全體廣播大聲公。
   - 中間的號碼：可用主機 IP (Usable Host IPs)。

2. 塊大小 (Block Size) 速算法：
   - 看到 /24：總共 256 個 IP (塊大小 = 256)。
   - 看到 /25：256 / 2 = 128 個 IP 一組。
   - 看到 /26：128 / 2 = 64 個 IP 一組。
   - 看到 /27：64 / 2 = 32 個 IP 一組 (遮罩尾數 256 - 32 = 224)。
   - 看到 /28：32 / 2 = 16 個 IP 一組 (遮罩尾數 256 - 16 = 240)。
   - 看到 /29：16 / 2 = 8 個 IP 一組 (遮罩尾數 256 - 8 = 248)。

二、 實戰範例 (10.200.20.0/27 再均分 4 個子網)：
--------------------------------------------------------------------------------
- 原始大小：32 個 IP (10.200.20.0 ~ 10.200.20.31)。
- 切 4 份：每份 32 / 4 = 8 個 IP (即 /29)。
  * 子網 1: 10.200.20.0  ~ 10.200.20.7   (網路: .0  / 廣播: .7)
  * 子網 2: 10.200.20.8  ~ 10.200.20.15  (網路: .8  / 廣播: .15)
  * 子網 3: 10.200.20.16 ~ 10.200.20.23  (網路: .16 / 廣播: .23)
  * 子網 4: 10.200.20.24 ~ 10.200.20.31  (網路: .24 / 廣播: .31)

一、 披薩大小對照表 (看到 CIDR 斜線，立刻知道有幾個號碼)
--------------------------------------------------------------------------------
- /24 = 256 個號碼 (整張大披薩)
- /25 = 128 個號碼 (對半切)
- /26 =  64 個號碼 (再對半切)
- /27 =  32 個號碼 (再對半切)
- /28 =  16 個號碼 (再對半切)
- /29 =   8 個號碼 (再對半切)

二、 兩大黃金解題公式 (不用算二進位)
--------------------------------------------------------------------------------
1. 算遮罩最後一格：
   公式：256 - (披薩大小) = 遮罩尾數
   例如 /27：256 - 32 = 224  -->  子網遮罩就是 255.255.255.224

2. 號碼牌三大角色：
   - 第一個號碼 (起點)：網路位址 (Network Address，大門招牌)
   - 最後一個號碼 (終點)：廣播位址 (Broadcast Address，大聲公廣播)
   - 中間全部號碼：可以給電腦/伺服器用的個人 IP

三、 實戰題目完全破解：目標 10.200.20.0/27
--------------------------------------------------------------------------------
【題目 1】求 10.200.20.0/27 的子網遮罩？
- 步驟：看到 /27 知道大小是 32。
- 計算：256 - 32 = 224。
- 答案：255.255.255.224

【題目 2】求 10.200.20.0/27 的廣播位址？
- 步驟：從 0 號開始數 32 個號碼牌 (號碼是 0 到 31)。
- 結尾：最後一個號碼就是 31。
- 答案：10.200.20.31

【題目 3 & 4】把這組網路平分成 4 個子網？
- 步驟：原本有 32 個號碼，32 / 4 = 8，代表每份分到 8 個號碼。
- 號碼牌分組清單：
  * 第 1 組：.0  到 .7   (開頭 .0  / 結尾 .7)
  * 第 2 組：.8  到 .15  (開頭 .8  / 結尾 .15)  --> 【題目 4 答案：10.200.20.15】
  * 第 3 組：.16 到 .23  (開頭 .16 / 結尾 .23)  --> 【題目 3 答案：10.200.20.16】
  * 第 4 組：.24 到 .31  (開頭 .24 / 結尾 .31)

【Hack The Box】MAC 位址、ARP 協定與內網欺騙攻擊核心筆記
================================================================================

一、 MAC 位址 (實體位址 / L2 鏈結層)
--------------------------------------------------------------------------------
1. 結構與格式：
   - 總長度 48 位元 (6 個位元組 / Octets)，以 16 進位表示 (如 00:0C:29:AB:CD:EF)。
   - 前 3 組 (前 24 bits)：OUI (組織唯一識別碼)，由 IEEE 分配給硬體製造商。
   - 後 3 組 (後 24 bits)：廠商自行分配的網卡流水號。
2. 特殊位址：
   - 全 FF 廣播位址：FF:FF:FF:FF:FF:FF (同網段所有設備強制接收)。
3. 攻擊手法：
   - MAC Spoofing (MAC 偽造)：偽裝成合法設備繞過 MAC 白名單存取控制。
   - MAC Flooding (泛洪攻擊)：發送大量偽造 MAC 塞爆交換器 CAM 表，使交換器
     降級成 Hub (廣播模式)，藉此監聽全網流量。

二、 ARP 協定運作 (位址解析協定 - 將 IP 轉為 MAC)
--------------------------------------------------------------------------------
1. ARP Request (廣播請求)：
   - 主機廣播詢問「Who has <目標 IP>? Tell <來源 IP>」，全網段設備皆收到。
2. ARP Reply (單播回應)：
   - 擁有該 IP 的主機會回應「<目標 IP> is at <自己的 MAC>」。
3. ARP 快取 (ARP Cache)：
   - 主機會將 IP 與 MAC 的對應關係快取在記憶體中，加速後續通訊。

三、 實戰攻擊：ARP 欺騙 (ARP Spoofing / Cache Poisoning)
--------------------------------------------------------------------------------
- 漏洞本質：ARP 協定無任何身分驗證，主機即使沒發出請求，也會強制更新快取。
- 攻擊手法：
  1. 攻擊者主動向受害者發送偽造的 ARP Reply：「路由器的 IP 其實是攻擊者的 MAC」。
  2. 攻擊者同時向路由器宣告：「受害者的 IP 其實是攻擊者的 MAC」。
- 達成效果：
  - 兩端流量皆流經攻擊者主機，形成中間人攻擊 (MITM)。
  - 攻擊者可利用 Ettercap、Bettercap、Cain & Abel 進行連線竊聽、密碼擷取與會話劫持。
- 防禦手段：
  - 動態 ARP 檢測 (DAI - Dynamic ARP Inspection)。
  - 綁定靜態 ARP 表條目。
  - 使用全站加密協定 (HTTPS/TLS、SSH、IPsec VPN)。

【Hack The Box】網路關鍵術語與核心協定速查筆記 (過濾冷門名詞版)
================================================================================

一、 核心高頻通訊協定 (靶機滲透、Nmap 掃描必看)
--------------------------------------------------------------------------------
1. SSH (Secure Shell / Port 22)：
   - 加密遠端文字終端連線，取代不安全的 Telnet，管理 Linux 主機首選。

2. FTP (File Transfer Protocol / Port 21)：
   - 檔案傳輸協定。滲透重點：檢查是否開放匿名登入 (anonymous:anonymous)。

3. SMB (Server Message Block / Port 445)：
   - Windows 內網檔案與印表機共用。滲透重點：極高價值目標，常存在
     認證缺失、永恆之藍 (MS17-010)、敏感組態檔外洩。

4. HTTP (Port 80) vs HTTPS (Port 443)：
   - HTTP：明文傳輸網頁協定，流量可被中間人 (MITM) 完全側錄。
   - HTTPS：HTTP 加上 TLS/SSL 加密封裝，保證傳輸內容機密性與完整性。

5. DNS (Domain Name System / Port 53)：
   - 網域名稱解析 (將網址轉為 IP)。滲透重點：區域傳送 (Zone Transfer) 洩漏子網域。

二、 網路邊界與連線技術
--------------------------------------------------------------------------------
1. NAT (Network Address Translation - 網路位址轉換)：
   - 將區域網路內部的大量私有 IP (如 192.168.x.x) 轉換為單一公網 IP 與外界通訊，
     兼具節省 IPv4 與單向邊界隱藏的效果。

2. VPN (Virtual Private Network) & IPsec：
   - 透過網際網路建立一條端到端的虛擬加密通道，打靶時連線 HTB 內網的主要方式。

3. VLAN (Virtual Local Area Network - 虛擬區域網路)：
   - 在第 2 層交換器上邏輯分割廣播網域，達成部門間網路隔離與存取控制。

三、 現代資安已淘汰之弱安全名詞 (見到代表存在安全缺陷)
--------------------------------------------------------------------------------
- WEP / WPA (TKIP)：早期 Wi-Fi 加密協定，演算法存在數學缺陷，可被極速破解。
- Telnet：未加密遠端連線 (Port 23)，帳號密碼於封包中明文傳輸。

【Hack The Box】常見網路協定端口與 TTL 判斷小抄
================================================================================

一、 TCP vs UDP 核心差異
--------------------------------------------------------------------------------
- TCP (傳輸控制協定)：
  * 特性：需三向交握 (SYN -> SYN/ACK -> ACK)，可靠傳輸、自動重傳、速度稍慢。
  * 適用：網頁瀏覽 (HTTP/HTTPS)、終端連線 (SSH)、檔案傳輸 (FTP)。
- UDP (用戶資料報協定)：
  * 特性：非連線導向 (無交握)，直接發送不檢查回報、速度極快、開銷低。
  * 適用：影片串流、VoIP 語音電話、DNS 快速查詢、DHCP 分配 IP。

二、 滲透必背常見端口 (Nmap 掃描核心)
--------------------------------------------------------------------------------
Port       協定       用途說明 / 滲透關注點
--------------------------------------------------------------------------------
21 (TCP)   FTP        檔案傳輸 (檢查匿名登入 anonymous)
22 (TCP)   SSH        加密遠端終端管理 (暴力破解、憑證登入)
23 (TCP)   Telnet     明文遠端終端 (弱安全協定，封包側錄帳密)
25 (TCP)   SMTP       郵件外發傳送
53 (U/T)   DNS        網域名稱解析 (Zone Transfer 區域傳送資訊洩漏)
80 (TCP)   HTTP       明文網頁服務 (Web 漏洞挖掘)
443 (TCP)  HTTPS      加密網頁服務 (Web 漏洞、憑證檢查)
445 (TCP)  SMB        Windows 檔案共用 (極高價值目標：EternalBlue、空密碼列舉)
1433 (TCP) MSSQL      微軟 SQL 資料庫
3306 (TCP) MySQL      MySQL / MariaDB 資料庫
3389 (TCP) RDP        Windows 遠端桌面連線

三、 ICMP 與 TTL 神技：快速識別作業系統 (OS Fingerprinting)
--------------------------------------------------------------------------------
在終端機執行：ping <目標 IP>，觀察回傳的 TTL 數值：
- TTL 初始值 64  (回傳約 64, 63, 62)  --> 目標作業系統為 Linux / macOS
- TTL 初始值 128 (回傳約 128, 127)    --> 目標作業系統為 Windows
- TTL 初始值 255 (回傳約 255, 254)    --> 目標為 網路設備 (Router/Cisco) 或 Solaris

※ 原理：封包每經過一台路由器跳轉 (Hop)，TTL 值自動減 1，歸 0 則被丟棄。

【Hack The Box】無線網路 (Wi-Fi / 802.11) 安全與攻擊核心筆記
================================================================================

一、 Wi-Fi 基礎元件與專有名詞
--------------------------------------------------------------------------------
1. SSID (Service Set Identifier)：無線網路的廣播名稱 (Wi-Fi 名字)。
2. AP / WAP (Wireless Access Point)：無線基地台，連接有線網路與無線設備的中心節點。
3. 802.11：IEEE 訂定的無線通訊協定標準家族。

二、 無線加密協定等級 (由弱至強)
--------------------------------------------------------------------------------
1. WEP (已淘汰)：
   - 採用弱 RC4 串流加密，因 IV (初始化向量) 長度太短且重複利用，
     攻擊者收集足夠封包後數分鐘即可暴力還原原始密碼。
2. WPA / WPA2：
   - 引入 TKIP (過渡) 與 AES-CCMP 高強度加密。
   - WPA-Personal (PSK)：單一共用密碼，易遭抓取 Handshake 後進行離線字典破解。
   - WPA-Enterprise (802.1X)：搭配 RADIUS 伺服器進行個別帳密/憑證認證。
3. WPA3：
   - 最新標準，採用 SAE (同時對等認證)，可免疫離線字典暴力破解。

三、 經典無線攻擊手法：Deauthentication Attack (分離 / 解除認證攻擊)
--------------------------------------------------------------------------------
1. 攻擊原理：
   - 利用 802.11 早期管理訊框 (Management Frames) 未加密之缺陷。
   - 攻擊者偽造 AP 的 MAC 位址，向目標客戶端發送 Deauth 封包強制中斷其連線。
2. 滲透目的：
   - 迫使目標客戶端與 AP 重新發起連線認證。
   - 攻擊者趁機側錄「四向交握 (WPA 4-Way Handshake)」封包。
   - 將抓到的 Handshake 檔案匯入 Hashcat 或 Aircrack-ng 進行離線密碼爆破。

四、 無線網路加固與常見迷思
--------------------------------------------------------------------------------
- 無效加固迷思：
  * 隱藏 SSID (停用廣播)：無法阻擋監聽工具 (有連線時依然會洩漏名稱)。
  * MAC 位址過濾：L2 MAC 位址極易被偽造 (MAC Spoofing) 繞過。
- 正確有效加固：
  * 全面禁用 WEP，升級至 WPA2/WPA3-Enterprise。
  * 啟用 802.11w (保護管理訊框 PMF)，防禦 Deauth 斷線攻擊。
  * 部署 EAP-TLS 基於數位憑證的雙向身分認證。
================================================================================

================================================================================
【Hack The Box】VPN (虛擬私人網路) 與 IPsec 協定核心筆記
================================================================================

一、 VPN 核心運作架構
--------------------------------------------------------------------------------
1. 目的：在不安全的公網環境上，建立一條端到端的虛擬加密通道，安全存取遠端內部網路。
2. 組成要素：
   - VPN Client (客戶端)：使用者端軟體 (如 OpenVPN、WireGuard、AnyConnect)。
   - VPN Server (伺服器)：邊界接收點，負責驗證身分、建立通道、配發內部虛擬 IP。
   - 加密與認證演算法：AES-256、SHA、憑證 (Digital Certificates) 交換。

二、 IPsec (網際網路安全協定) 核心機制
--------------------------------------------------------------------------------
在 L3 網路層提供資料機密性、完整性與身分驗證：
1. 核心次協定：
   - AH (Authentication Header)：僅提供身分驗證與資料完整性，不提供加密功能。
   - ESP (Encapsulating Security Payload)：提供完整加密 (Confidentiality) 與驗證。
2. 兩種運作模式：
   - Transport Mode (傳輸模式)：僅加密資料負載 (Payload)，保留原始 IP 標頭 (主機對主機)。
   - Tunnel Mode (隧道模式)：將原始 IP 標頭與資料完整打包加密，外層貼上新 IP 標頭 (站點對站點 VPN)。

三、 滲透測試與打靶實務
--------------------------------------------------------------------------------
- HTB 連線：透過 `openvpn <設定檔.ovpn>` 建立隧道，取得 tun0 虛擬網卡與 10.10.x.x 內網 IP。
- 滲透攻擊面：
  * IKE (Port 500 UDP)：探測 VPN 握手協定弱點、提取 Aggressive Mode 的預共享金鑰 (PSK)。
  * 邊界設備漏洞：未修補之 SSL-VPN 邊界漏洞 (如 FortiOS、Ivanti 漏洞) 為內網突破首選路徑。
================================================================================

================================================================================
【Hack The Box】VLAN 封包分析、跳躍攻擊與 Cisco 協定核心筆記
================================================================================

一、 Wireshark / Tshark VLAN 流量過濾指令
--------------------------------------------------------------------------------
1. Wireshark 顯示過濾語法：
   - `vlan`              : 只抓取帶有 802.1Q 標籤的封包。
   - `vlan.id == 10`     : 只看特定 VLAN 10 的通訊流量。
2. Tshark 命令列快速列舉封包中的所有 VLAN ID：
   - `tshark -r <檔案.pcapng> -T fields -e vlan.id | sort -n -u`

二、 經典 VLAN 跳躍攻擊 (VLAN Hopping)
--------------------------------------------------------------------------------
1. 交換器欺騙 (Switch Spoofing)：
   - 成因：交換器連接埠啟用 DTP (動態幹線協定)，且未關閉協商。
   - 工具：Yersinia。
   - 攻擊：攻擊者發送 DTP 封包偽裝成交換器，建立 Trunk Link，竊取全網段流量。
   - 防禦：將邊界接入端埠強制設為 Access 模式 (switchport mode access)，關閉 DTP。

2. 雙重標籤 (Double Tagging)：
   - 成因：利用原生 VLAN (Native VLAN) 標籤在傳輸時會被剝離的特性。
   - 攻擊：構造內外雙層 802.1Q 標籤封包，外層拆掉後直接送達第二台交換器的目標 VLAN。
   - 防禦：勿使用 VLAN 1 作為 Native VLAN，或對 Native VLAN 強制打上標籤。

三、 Cisco 特有協定與情蒐價值
--------------------------------------------------------------------------------
1. CDP (思科探索協定 / L2 廣播)：
   - 特性：思科設備預設定時向內網廣播自身身分 (未加密)。
   - 滲透情蒐：被動監聽即可獲取設備主機名、硬體型號 (Platform)、IOS 版本、管理 IP。
   - 防禦：終端接入埠全面停用 (no cdp run / no cdp enable)。

2. STP (生成樹協定)：
   - 目的：避免交換器之間產生迴圈與廣播風暴。
   - 滲透思維：攻擊者可偽造 BPDU 封包搶奪「根橋 (Root Bridge)」地位以劫持拓撲流量。

================================================================================
【Hack The Box】密鑰交換機制 (Key Exchange) 與 VPN (IKE) 弱點筆記
================================================================================

一、 核心演算法角色定位 (了解用途即可，不背數學)
--------------------------------------------------------------------------------
1. Diffie-Hellman (DH / ECDH)：
   - 核心功能：讓通訊雙方在「完全不安全的公開通道」上，安全協商出一組共享密鑰。
   - 致命缺陷：原生 DH 缺乏身分認證機制，易遭中間人攻擊 (MITM)。
   - 現代改進：ECDH (橢圓曲線 DH)，以更短金鑰提供同等安全度與更高效能。

2. 非對稱公私鑰 (RSA / ECDSA)：
   - 公鑰加密/驗證簽章、私鑰解密/產生簽章。
   - 用於身分驗證 (數位簽章)，防止通訊對象被冒充。

二、 IKE (網際網路金鑰交換協定) 與滲透利用點
--------------------------------------------------------------------------------
- 用途：IPsec VPN 建立加密連線前的金鑰協商協定 (UDP Port 500)。
- 兩大協商模式：
  1. Main Mode (主模式)：
     - 交換 6 個封包，三階段協商，身分資訊全程受加密保護，安全性高。
  2. Aggressive Mode (激進模式)：
     - 僅交換 3 個封包以求高速，身分未受保護。
     - ★ 實戰漏洞點：伺服器會在握手階段直接將 Pre-Shared Key (PSK) 雜湊
       回傳給客戶端。

三、 實戰打靶攻擊指令 (IKE 探測與 PSK 暴力破解)
--------------------------------------------------------------------------------
1. 探測 VPN 是否開啟弱點激進模式：
   ike-scan -A -M -P <目標 IP>
2. 擷取 PSK 雜湊並輸出檔案：
   ike-scan -A -M --pskexport=hash.txt <目標 IP>
3. 丟入 Hashcat 進行離線字典檔暴力破解：
   hashcat -m 5400 hash.txt rockyou.txt

【Hack The Box】身分驗證協定 (Authentication) 核心考點筆記
================================================================================

一、 內網滲透王者：Kerberos (Port 88)
--------------------------------------------------------------------------------
1. 定位：Active Directory (AD 企業網域) 的核心認證協定，基於 Ticket (票券) 機制。
2. 核心運作流程：
   - 使用者向 KDC (金鑰發放中心) 驗證帳密。
   - KDC 簽發 TGT (票券授權票券)。
   - 使用者憑 TGT 換取特定服務 (如 SMB、SQL) 的 Service Ticket，無須重複輸入密碼。
3. 實戰經典攻擊面：
   - Kerberoasting：請求 SPN 服務票券並離線暴力破解服務帳號密碼。
   - AS-REP Roasting：針對未啟用 Kerberos 預先認證的帳號抓取 Hash 爆破。
   - Pass-the-Ticket (PtT)：注入竊取之合法票券劫持權限。

二、 Web 應用認證與授權協定
--------------------------------------------------------------------------------
1. OAuth 2.0 (授權框架)：
   - 第三方授權標準 (如「透過 Google / GitHub 登入」)。
   - 特色：使用者無需將密碼交給第三方，僅透過 Access Token 授權最小權限存取。
2. SAML 2.0 / OpenID Connect (OIDC)：
   - 常用於企業 SSO (單一登入)，透過身分識別提供商 (IdP) 集中認證。
3. MFA (多因素驗證)：
   - 結合「你知道的 (密碼) + 你擁有的 (手機/硬體金鑰) + 你本身的 (生物特徵)」。

三、 弱安全淘汰協定 (滲透測試視角)
--------------------------------------------------------------------------------
- PAP (密碼驗證協定)：完全明文傳輸帳號密碼，封包側錄即可秒殺。
- CHAP / MS-CHAPv2：早期握手挑戰協定，存在演算法缺陷，易遭抓包暴力破解。
- LEAP：思科早期 Wi-Fi 認證協定，採用弱 MS-CHAPv2，已被 EAP-TLS / PEAP 取代。

【Hack The Box】IP/TCP/UDP 標頭結構與 Traceroute 原理筆記
================================================================================

一、 IP 標頭實戰關鍵欄位 (不背細節，抓重點)
--------------------------------------------------------------------------------
1. TTL (Time to Live - 存活時間)：
   - 防止封包在網路中無窮迴圈，每經過一個 Hop 減 1，為 0 時丟棄並回報 ICMP。
   - 實戰功能 A：OS 指紋識別 (TTL ~64 為 Linux/Mac，~128 為 Windows)。
   - 實戰功能 B：Traceroute (路由追蹤) 的底層核心原理。

2. Identification (IP ID)：
   - 用於封包分片 (Fragmentation) 重組時識別同一份資料。
   - 滲透實務：早期 Idle Scan (殭屍主機掃描 - Nmap -sI) 就是利用 IP ID 
     是否連續遞增來判定目標連接埠是否開放；亦可用於關聯不同 IP 是否源自同一實體主機。

二、 Traceroute 運作原理 (TTL 漸增探測法)
--------------------------------------------------------------------------------
1. 發送第一批封包 (TTL = 1)：
   - 第一跳路由器將 TTL 減為 0，丟棄封包並回傳 `ICMP Type 11 (Time-to-Live Exceeded)`。
   - 探測端藉此獲得第 1 個路由節點的 IP。
2. 發送第二批封包 (TTL = 2)：
   - 第二跳路由器回傳 ICMP 逾時，取得第 2 個節點 IP。
3. 依此類推遞增 TTL，直到抵達最終目標主機 (目標主機回應 ICMP Echo Reply 或 Port Unreachable)。

三、 TCP 握手與 ISN 序號
--------------------------------------------------------------------------------
1. ISN (Initial Sequence Number - 初始序號)：
   - TCP 三向交握時由雙方各自隨機生成的起始序列號碼，確保封包順序與連線唯一性。
2. 盲目欺騙 (Blind Spoofing)：
   - 若目標主機的 ISN 生成演算法存在規律 (可被預測)，攻擊者即使接收不到回包，
     亦能偽造來源 IP 並精確猜中 ACK 確認號，達成單向 TCP 會話劫持。
================================================================================

【Hack The Box】密碼學 (Cryptography) 與加密模式速查筆記
================================================================================

一、 對稱式加密 (Symmetric Encryption)
--------------------------------------------------------------------------------
1. 定位：加密與解密使用「同一把私鑰 (Shared Secret)」。
2. 特點：運算速度極快、消耗資源低，適合傳輸大量資料。
3. 代表演算法：
   - DES / 3DES：早期標準，金鑰過短 (56-bit)，已被暴力破解淘汰。
   - AES (進階加密標準)：現代主流標準，金鑰長度有 128 / 192 / 256 位元，安全度極高。

二、 非對稱式加密 (Asymmetric Encryption / 公私鑰)
--------------------------------------------------------------------------------
1. 定位：使用一對金鑰 (Public Key 公鑰加密 / Private Key 私鑰解密)。
2. 特點：解決了金鑰安全分發問題，支援數位簽章 (Digital Signatures)，但運算開銷大。
3. 代表演算法：
   - RSA：基於大質數分解困難度。
   - ECC (橢圓曲線密碼學)：以更短的金鑰達到與 RSA 同等的安全性，運算更快。
4. 混合加密架構 (HTTPS / SSH / VPN)：
   - 先用「非對稱加密」安全協商金鑰，再以「對稱加密 (AES)」高速傳輸資料本體。

三、 分組加密運作模式 (Block Cipher Modes)
--------------------------------------------------------------------------------
- ECB (電子密碼簿模式 - 弱安全)：
  * 缺點：相同的明文區塊永遠產生相同的密文，無法隱藏資料結構特徵。
  * 滲透：常見區塊置換攻擊 (Block Shuffling) 或重放攻擊。
- CBC (密碼區塊鏈模式)：
  * 引入 IV (初始化向量)，前一區塊的密文與下一區塊做 XOR 運算。
  * 滲透：實作不當易受 Padding Oracle (填補 Oracle 攻擊)。
- CTR (計數器模式) & GCM (伽羅瓦/計數器模式)：
  * 現代主流模式，速度快且支援平行運算；GCM 額外具備驗證資料完整性功能 (AEAD)。
