【資安筆記】Hack The Box - 網路流量分析 (NTA) 基礎核心
==================================================

一、何謂 NTA (Network Traffic Analysis)
- 定義：分析封包與通訊協定，建立網路行為基準線、監控異常活動與潛在威脅。
- 核心價值：
  1. 偵測匿蹤攻擊（攻擊者常偽裝成正常流量以躲避防禦）。
  2. 事故調查、取證分析（如偵測大量 SYN 封包代表 portscan 掃描行為）。
  3. 日常應用：收集分析封包、建立基線、識別異常協定/非標準連接埠流量、偵測傳輸中的惡意軟體。

二、必備基礎概念
1. TCP/IP 與 OSI 模型：掌握各層運作與交換/路由概念。
2. 常用連接埠與協定：快速識別正常與異常流量（如 80/443、DNS 53、SMB 445 等）。
3. IP 封包與子層概念：
   - TCP：連線導向、可靠傳輸、可重組與追蹤串流內容。
   - UDP：速度快、無連線、不保證完整性。
4. 協定封裝 (Encapsulation)：逐層解構標頭與特徵以抽取鑑識資訊。

三、常見交通分析工具與技術
1. 封包擷取與命令列工具：
   - tcpdump：Linux 最經典 CLI 封包擷取與分析工具（基於 libpcap）。
   - tshark：Wireshark 的命令列版本（CLI）。
   - ngrep：網路流量版的 grep，可透過正規表達式與 BPF 匹配 Hex/ASCII 內容（如 HTTP、FTP 明文）。
   - tcpick：專門追蹤與重組 TCP 串流內容的命令列工具。
2. 圖形化分析工具：
   - Wireshark：最強大且最普及的 GUI 網路分析軟體，支援深度封包解析與重組。
3. 流量獲取與集中分析平台：
   - Network Taps（硬體測試分流器）：實體被動分流設備，不干擾主線路流量。
   - Port Mirroring / SPAN：交換機通訊埠鏡像技術，複製特定流量至分析埠。
   - Elastic Stack (ELK)：集中收集、解析、搜尋與視覺化大量日誌與封包。
   - SIEM (如 Splunk)：安全性資訊與事件管理平台，關聯分析異常日誌與警報。

四、BPF (Berkeley Packet Filter) 語法 (重點核心！)
- 作用：核心層級的封包過濾機制，tcpdump、Wireshark 等工具共用。
- 重要性：在封包進入分析工具前即進行高效率過濾，大幅降低雜訊並提升解碼速度。

五、NTA 標準工作流程 (Workflow)
1. 流量接收 (Ingest Traffic)：確定置放與分流位置，進行封包擷取或接收 TAP/SIEM 流量。
2. 透過過濾降低雜訊 (Reduce Noise by Filtering)：排除廣播、組播與正常高頻雜訊，聚焦目標區段。
3. 分析與探索 (Analyze and Explore)：
   - 流量是明文還是加密？
   - 是否有未經授權存取機敏資訊？
   - 不尋常的主機或連接埠通訊行為？
4. 檢測與警報 (Detect and Alert)：
   - 識別非預期行為（異常流量、異常設備連線）。
   - 搭配 IDS/IPS 進行特徵比對與啟發式分析。
5. 修復和監控 (Remediate and Monitor)：採取阻斷/修補措施，並持續監控確認威脅已被根除。

【靶機除錯急救包】只在「連不上」或「拿到 pcap」時打開
==================================================

狀況 1：拿到一個題目附帶的 xxx.pcap 檔案
--------------------------------------------------
1. 用 Wireshark 打開。
2. 上方過濾列直接打（找明文連線）：
   http || ftp || telnet
3. 在任何一筆封包上按右鍵 -> Follow -> TCP Stream。
   - 看到紅藍文字：直接看有沒有帳號、密碼、Token、敏感目錄。
4. 按 Ctrl + F（搜尋）：
   - 選擇「Packet bytes」
   - 關鍵字打：password、admin、login、flag

--------------------------------------------------
狀況 2：Reverse Shell 彈不回來 / 攻擊腳本卡住
--------------------------------------------------
1. 開新分頁，輸入這行指令開始抓包（監聽 VPN 網卡）：
   sudo tcpdump -i tun0 host <靶機IP> -nn

2. 重新打一次你的攻擊或 Payload，看終端機跳出的畫面：
   - 完全沒動靜：靶機根本沒收到，通常是防火牆擋住，換 Port 試試（改用 80, 443, 53）。
   - 有看到封包，但帶有 [R] (RST)：靶機主動拒絕連線，代表目標服務沒開或埠號打錯。
   - 看到 [S] (SYN) 有發出去且對方有回 [S.] (SYN-ACK)：網路通暢，純粹是你的 Payload/Exploit 寫錯或版本不符。

【資安筆記】網路入門 - 第 1 至 4 層核心精華
==================================================

一、OSI vs TCP/IP 概念對應
- OSI 七層（理論模型）：應用、展示、會議、傳輸、網路、資料鏈結、實體
- TCP/IP 四層（實作模型）：
  1. Application (應用層) -> 資料 (Data)
  2. Transport (傳輸層)   -> 區段/資料報 (Segment / Datagram)
  3. Internet (網際網路層)-> 封包 (Packet)
  4. Link (鏈結層)        -> 訊框/位元 (Frame / Bits)
- 封裝 (Encapsulation)：資料由上往下送時，每層都會加入該層的標頭 (Header)；接收端反向逐層拆解。

二、二層 vs 三層：MAC 與 IP
1. MAC 地址 (Layer 2 Data-Link)：
   - 長度：48-bit (6 個十六進位組，如 88:66:5a:11:bb:36)。
   - 用途：區域網路 (LAN) 內部設備尋址與交換機轉發。
2. IP 地址 (Layer 3 Network)：
   - 用途：跨網段路由 (Routing) 尋址。
   - IPv4：32-bit (如 192.168.86.243)。
   - IPv6：128-bit (解決 IPv4 位址耗盡問題，支援更大的定址空間與原生安全性)。

三、傳輸層核心：TCP vs UDP (Layer 4)
- TCP (Transmission Control Protocol)：
  * 特性：連線導向 (Connection-oriented)、可靠傳輸、錯誤重傳、依序重組。
  * 適用：SSH、HTTP/HTTPS、FTP、Webshell 反彈連線 (需要資料保證完整)。
- UDP (User Datagram Protocol)：
  * 特性：非連線導向 (Connectionless)、無交握機制、速度極快、不保證送達。
  * 適用：DNS 查詢、SNMP、視訊串流、VoIP。

四、TCP 連線建立與結束機制 (必考實戰點)
1. TCP 三向交握 (Three-Way Handshake) - 建立連線：
   - Step 1: Client -> Server 發送 [SYN] (請求同步序號)
   - Step 2: Server -> Client 回應 [SYN, ACK] (同意連線並確認)
   - Step 3: Client -> Server 發送 [ACK] (連線正式建立，開始送資料)
2. TCP 拆除連線 (Connection Termination)：
   - 雙方發送 [FIN, ACK] 確認通訊結束並釋放連線。
3. 滲透/打靶對照：
   - nmap -sS (SYN Scan)：送 SYN -> 收 SYN/ACK (代表 Port 開放) -> 主動發 RST 中斷，不走完第三步 ACK (匿蹤/快速)。

【資安筆記】網路入門 - 第 5 至 7 層 (應用層協定)
==================================================

一、HTTP (HyperText Transfer Protocol)
- 常用 Port：TCP 80, 8080
- 特性：無狀態、完全「明文傳輸」（無加密），封包側錄即可見帳密。
- 常見 HTTP 請求方法 (Methods)：
  * GET：請求讀取網頁/資源。
  * POST：向伺服器提交資料（如登入表單、留言、上傳檔案）。
  * PUT：上傳/替換目標資源（滲透常測是否能直接 PUT 上傳木馬）。
  * DELETE：刪除伺服器上的資源。
  * OPTIONS：查詢伺服器支援哪些請求方法（探測用）。
  * HEAD：只取 HTTP 標頭，不抓內容（快速檢查存活）。

二、HTTPS (HTTP Secure)
- 常用 Port：TCP 443, 8443
- 機制：HTTP + TLS/SSL 加密。
- TLS 握手重點：
  * Client Hello / Server Hello：協商加密演算法與版本。
  * 憑證交換 (X.509)：伺服器向客戶端證明身分。
  * 產生對稱金鑰：完成後所有內容皆以「Application Data」密文傳輸，防範中間人竊聽。

三、FTP (File Transfer Protocol)
- 常用 Port：TCP 21 (控制/指令通道)、TCP 20 (資料傳輸通道)
- 特性：老舊、完全「明文傳輸」。
- 兩種模式：
  * 主動模式 (Active)：伺服器主動連回客戶端資料埠（易被客戶端防火牆擋住）。
  * 被動模式 (Passive / PASV)：客戶端主動連伺服器開啟的高位埠（現代網路環境常用）。
- 常見命令：
  * USER：指定登入使用者名稱（常有 anonymous 匿名登入）。
  * PASS：傳送密碼（封包直接肉眼可讀）。
  * LIST / RETR / STOR：列出目錄 / 下載檔案 / 上傳檔案。

四、SMB (Server Message Block)
- 常用 Port：TCP 445 (現代直接走 TCP)、舊版走 NetBIOS (UDP 137, 138 / TCP 139)
- 特性：Windows 內網共用資料夾、印表機與命名管道的核心協定。
- 滲透與打靶重點：
  * 匿名/訪客登入 (Anonymous / Guest Access)：常有未授權資料夾可下載機敏設定檔。
  * 暴力破解識別：封包中若出現大量 Session Setup Request 與 LOGON_FAILURE，代表正在遭受字典爆破。
  * 橫向移動目標：Pass-the-Hash、PsExec 等工具多依賴 SMB 進行遠端執行。

【資安筆記】流量分析過程與架構 (Analysis Process)
==================================================

一、流量分析核心定義
- 透過檢視封包事件與流程，判定影響、追查來源並採取防禦行動。
- 核心精神：建立「正常基準線 (Baseline)」，才能在第一時間辨別何謂「異常偏離」。

二、流量擷取的兩大模式 (Capture Modes)
1. 被動式 (Passive)：
   - 作法：透過 SPAN/Mirror Port (埠鏡像) 或 Network TAP (分流器) 複製一份流量。
   - 特點：不干擾正式線路傳輸、零延遲，純旁路監聽。
2. 主動式 / 串接 (Active / In-line)：
   - 作法：分析設備直接串接在網路主線路正中央 (如 IPS / 深度封包檢測)。
   - 特點：具備即時阻斷 (Drop/Block) 攻擊能力，但若設備當機可能造成網路斷線。

三、分析依賴條件 (Dependencies)
- 權限 (Permission)：必須具備合法授權方可側錄網路。
- 埠鏡像 (Mirror Port)：交換機需設定將流量複製送至分析埠。
- 擷取工具 (Capture Tool)：tcpdump (CLI)、Wireshark (GUI) 等。
- 運算與儲存資源 (Storage & Compute)：全量封包 (PCAP) 體積極大，需評估硬碟與解析效能。

四、打靶機與實務分析技巧 (找異常特徵)
1. 協定與埠號異常：
   - 內網主機在非上班時間頻繁連線至非標準埠 (如 8080, 4444)。
   - 一般辦公區主機突發性出現大量 445 (SMB) 或 RDP/SSH 連線 (疑似橫向移動或爆破)。
2. Wireshark 快速過濾與統計手法：
   - Statistics -> Protocol Hierarchy：快速掌握流量組成。
   - Statistics -> Conversations：找出傳輸量最大、對話次數最多的異常連線 IP。

【資安筆記】流量分析實務與調查工作流程 (SOP)
==================================================

一、分析的四大思維階段 (Analytical Framework)
1. 描述性分析 (Descriptive)：定義問題本質
   - 發生了什麼事？(如資料外洩、疑似被植入挖礦軟體)
   - 定義範圍與時間：鎖定特定時間區間 (如過去 2 小時內)。
   - 鎖定目標與協定：定義網段 (如 192.168.100.0/24) 與協定 (HTTP / FTP)。
2. 診斷性分析 (Diagnostic)：深入找原因與關聯
   - 擷取/提取目標資料 (PCAP 或 NetFlow)。
   - 透過過濾排除無關雜訊，聚焦在疑似請求 (如 GET 請求含有 .exe)。
   - 深入剖析協定細節 (如 ftp-data 傳輸內容、特定 URL 路徑)。
3. 預測性分析 (Predictive)：推測威脅軌跡與未來影響
   - 建立時間線筆記 (涉及的主機 IP、下載的時間點、通訊的外部伺服器)。
   - 對比威脅情資 (與已知攻擊工具特徵進行比對)。
4. 規範性分析 (Prescriptive)：修復與防禦決策
   - 提出改善防禦措施 (如隔離受害主機、更新防火牆阻斷名單)。

二、流量調查實戰核心排查手法 (找線索必備)
1. 從標準外聯協定切入 (Standard Protocols)：
   - 先過濾 HTTP/S、FTP、DNS、外聯 TCP/UDP，排除正常辦公流量。
   - 檢查是否出現不該對外開放的協定 (如外聯的 RDP 或 Telnet)。
2. 尋找週期性行為 (Patterns / Beaconing)：
   - 留意是否有特定主機以「固定頻率」向外發送微小請求 (典型的 C2 殭屍網路回連特徵)。
3. 檢查主機間水平通訊 (Host to Host)：
   - 正常區域網路中，終端設備 (PC) 彼此極少互相通話。
   - 若出現大量 PC 之間的直連流量，強烈懷疑為內網橫向移動 (Lateral Movement)。
4. 留意異常與唯一事件 (Unique Events)：
   - 平時很少連線、突然只連過一次的外網 IP。
   - User-Agent 欄位與內部標準瀏覽器不相符的 HTTP 請求。
