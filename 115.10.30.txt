# 學習日誌：Bash 腳本與環境除錯筆記

## 1. 任務核心邏輯
- **目標**：將指定初始字串進行 35 次 Base64 編碼，並輸出第 35 次結果的長度。
- **執行順序**：
  - 必須「先加工，再判斷」：在迴圈內先執行 `var=$(echo $var | base64)`，接著再進入 `if` 條件。
  - 若將 `if` 放在加工指令前，抓到的會是第 34 輪的舊資料，而非第 35 輪的新成品。
- **累積機制**：
  - 變數 `var` 僅是抽屜標籤（可自由命名），但必須使用 `var=$(echo $var | ...)` 讓每次編碼結果覆蓋回變數本身，達成滾雪球累加效果；不可寫死初始字串。

## 2. 條件判斷與運算子對照表
- **`if` 語法規範**：
  - 結構為 `if [ 條件 ]; then ... fi`。
  - 中括號 `[` 右側與 `]` 左側**必須保留空格**，否則 Bash 會判定為語法錯誤。
- **數值比較運算子**（專門用於純數字比較）：
  - `-eq`（Equal）：等於，例如 `[ $counter -eq 35 ]`
  - `-ne`（Not Equal）：不等於，例如 `[ $counter -ne 35 ]`
  - `-gt`（Greater Than）：大於，例如 `[ $counter -gt 35 ]`
  - `-ge`（Greater or Equal）：大於或等於，例如 `[ $counter -ge 35 ]`
  - `-lt`（Less Than）：小於，例如 `[ $counter -lt 35 ]`
  - `-le`（Less or Equal）：小於或等於，例如 `[ $counter -le 35 ]`
- **字串比較運算子**（專門用於文字比對）：
  - `=` 或 `==`：字串相符，例如 `[ "$var" = "admin" ]`
  - `!=`：字串不相符，例如 `[ "$var" != "admin" ]`
  - `-z`：字串長度為 0（空字串）
  - `-n`：字串長度大於 0（非空字串）

## 3. 長度測量指令 (`wc`)
- `wc -m`：計算字元數（Characters）。
- `wc -c`：計算位元組數（Bytes）。
- **Base64 特性**：
  - Base64 編碼結果僅包含 ASCII 字元（A-Z、a-z、0-9、+、/、=）。
  - 在 UTF-8 編碼中，1 個 ASCII 字元剛好佔用 1 個 Byte，因此本題中 `wc -m` 與 `wc -c` 計算結果完全一致。

## 4. 環境與編輯器除錯紀錄
- **VS Code 檔案覆寫衝突**：
  - 當外部終端機指令（如 `sed`）修改了檔案，而 VS Code 編輯器內也有未儲存的異動時，會產生版本衝突。
  - 單純按 `Ctrl + S` 可能會無效，必須手動點擊編輯器右下角彈出的「覆寫 (Overwrite)」提示，標籤頁旁的實心白點才會消失並真正寫入磁碟。
- **Windows / Linux 換行符號問題 (`\r`)**：
  - 在 Windows 下建立或編輯的檔案預設帶有 CRLF（`\r\n`），在 Linux 環境執行時會導致直譯器報錯（如 `command not found` 或語法錯誤）。
  - 執行前可使用指令去除多餘字元：`sed -i 's/\r$//' <檔名>`。

## 5. 完整正確腳本範例
```bash
#!/bin/bash

# 定義初始加工字串
var="nef892na9s1p9asn2aJs71nIsm"

# 執行 40 次迴圈
for counter in {1..40}
do
    # 步驟 1：先產生當輪編碼結果
    var=$(echo$var | base64)

    # 步驟 2：使用數值比較運算子判斷是否為第 35 輪，若是則輸出長度
    if [ $counter -eq 35 ]; then
        echo $var | wc -c
    fi
done

# 學習日誌：Bash 陣列（Array）索引與引號規則

## 1. 陣列的基礎定義
- **宣告方式**：使用小括號 `( )`，預設以「空格」區隔不同元素。
- **雙引號的作用**：
  - 用雙引號 `" "` 包起來的文字，即使中間有空格，也會被視為「同一個元素」。
  - 範例：
    ```bash
    domains=(
      "[www.inlanefreight.com](https://www.inlanefreight.com) ftp.inlanefreight.com vpn.inlanefreight.com"
      www2.inlanefreight.com
    )
    ```
    - 前面被引號包住的整串文字為「第 1 個元素」。
    - 後面的 `www2.inlanefreight.com` 為「第 2 個元素」。
    - 整個陣列裡面總共只有 2 個元素。

## 2. 索引編號（Index）提取規則
- **正向索引（從 0 開始）**：
  - 電腦數陣列永遠由 `0` 起算，不是從 1 開始。
  - `${domains[0]}`：取得第 1 個元素（即引號內的那整大串網址）。
  - `${domains[1]}`：取得第 2 個元素（即 `www2.inlanefreight.com`）。
- **反向索引（負數）**：
  - 負數代表從隊伍的尾端倒著往前數。
  - `${domains[-1]}`：取得最後一個元素。
  - 在本題中只有兩個元素，因此 `${domains[1]}` 與 `${domains[-1]}` 取出的都是 `www2.inlanefreight.com`。

## 3. 提取語法注意事項
- 取值時變數外面必須加上大括號：`${陣列名[索引]}`。
- 題目要求提交列印特定項目的 echo 語句，答案必須包含指令本身：
  `echo ${domains[1]}`
一個人看一行字：肉眼直接看最後面，當然最快。

讓電腦幫你打工處理未知、大量資料：你必須給它語法 [-1]，它才知道「不管資料多長，反正永遠幫我拿最後那個」。

# Bash 核心觀念與語法筆記

## 一、變數的基本規則：存取與讀取

* **存入 / 賦值（不加 $）**
  * 建立變數或修改內容時，等號左邊不可加 `$`。
  * 範例：`var="hello"`、`name="Alex"`

* **取出 / 讀取（必須加 $）**
  * 要使用變數裡面的值（印出、運算、傳遞）時，必須加 `$`。
  * 範例：`echo $var`（印出 hello）
  * 說明：若寫 `echo var`，系統只會把「v-a-r」當作純文字印出。

---

## 二、重點語法速查

### 1. 指令輸出存入變數：`$( 指令 )`
* **用途**：執行括號內的指令，並將執行結果回傳賦值給變數。
* **範例**：
  * `var=$(echo $var | base64)`：將 `$var` 丟給 `base64` 編碼後，把結果存回 `var`。
  * `today=$(date +%Y%m%d)`：取得當前日期存入變數。

### 2. 計算字串長度：`${#變數名稱}`
* **用途**：在變數名稱前加 `#`，可取得該字串的「總字元數量」。
* **範例**：
  * 若 `name="apple"`，則 `${#name}` 會回傳 `5`。
  * `[ "${#var}" -gt 113450 ]`：判斷字串長度是否大於 113450（`-gt` 即 Greater Than）。

### 3. 字串包含比對：`[[ "$A" == *"$B"* ]]`
* **用途**：檢查字串 `$A` 內是否夾帶 `$B` 的內容。
* **符號解析**：
  * `[[ ... ]]`：支援進階字串比對與萬用字元的條件判斷。
  * `*`（星號）：代表前面或後面接任何字元皆可（模糊比對）。
* **範例**：
  * `[[ "$var" == *"$value"* ]]`：檢查 `$var` 之中是否有出現 `$value` 的文字。

### 4. 擷取末端字元：`tail -c 數量`
* **用途**：透過管線 `|` 接過文字，只取出結尾指定 Byte/字元數。
* **範例**：
  * `echo "$var" | tail -c 20`：抓出該變數內容的最後 20 個字元。

---

## 三、Hack The Box 範例腳本結構解析

```bash
#!/bin/bash

# 1. 定義初始變數（存入不加 $）
var="3kHk7CsjjL2KHF7wX7LjLs"
value="cGRmRE42bEQpaE1JYTk1aGZ0MCg="

# 2. 迴圈執行 40 次
for i in {1..40}
do
    # 拿出舊的 $var 加密，並存回 var
    var=$(echo$var | base64)

    # 3. 雙條件檢查：包含目標字串 且 長度大於 113450
    if [[ "$var" == *"$value"* ]] && [ "${#var}" -gt 113450 ]; then
        # 4. 符合條件時，截取最後 20 個字元印出
        echo "$var" | tail -c 20
    fi
done

# 資安實戰與觀念筆記：Bash 自動化與邏輯拆解

## 一、核心觀念：我學這個到底在幹嘛？

不要去硬背冷門符號，資安腳本的本質永遠只有四個步驟：
「輸入資料 ➔ 加工處理 ➔ 條件判斷 ➔ 輸出成果」。

### 1. 為何要「連續處理並覆蓋存回」（如：var=$(echo$var | base64)）？
* **邏輯觀念**：吹氣球原理。每一次迴圈都要拿「上一次變長後的結果」繼續吹，資料才會滾雪球放大。如果不存回原本的變數，每次都只會拿初始字串做一次運算，永遠長不大。
* **實務應用**：
  * **惡意程式去混淆**：許多木馬或 Payload 為了躲防毒，會經過 3～5 層連續 Base64 編碼。寫一個 3 行迴圈自動連續解碼並覆蓋，直到解出看得懂的明文。
  * **密碼 Hash 運算**：某些驗證機制要求連續做多次雜湊（如 MD5/SHA256 迭代）。

### 2. 雙條件檢查：一行 && 與 拆成兩行 if（巢狀判斷）
在 Bash 中，若不想把條件用 `&&` 擠在同一行，拆成兩層 `if` 邏輯完全相同，程式可讀性更高：

```bash
# 寫法 A：使用 && 連接（單層判斷） tail(尾巴 最後) 
if [[ "$var" == *"$value"* ]] && [ "${#var}" -gt 113450 ]; then
    echo "$var" | tail -c 20
fi

# 寫法 B：拆成兩層（巢狀 if，直覺好懂）
if [[ "$var" == *"$value"* ]]; then    #檢查var裡面有帶value內容   
    if [ "${#var}" -gt 113450 ]; then  #var長度有沒有113450
        echo "$var" | tail -c 20
    fi
fi
